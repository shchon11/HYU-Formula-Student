## Key Findings

### 1. Margin-only does not help

`c04_margin_only` kept `sparse_near_min_points=4` and `sparse_mid_min_points=3`,
but increased bbox margin to `8.0 / 0.25`. It produced no extra cone.

This means the missed cone was not primarily caused by too-small bbox expansion.

### 2. Near-only relaxation does not help

`c06_near_relaxed` lowered only near support from 4 to 3 and did not improve output.

This indicates the recovered cone is being treated as mid-range rather than near-range.

### 3. Mid-range minimum points is the main lever

Every practical successful conservative combo includes:

```text
sparse_mid_min_points: 2
```

The decisive detection appears repeatedly as:

```text
yellow raw=4 roi=2 cl=0 assigned_sparse
```

That detection has only 2 ROI support points, so the default mid-range threshold
of 3 rejects it. Lowering mid support to 2 accepts it.

### 4. Aggressive points recovers the most but is risky

`c07_aggressive_points` produced the highest count:

```text
blue=2 yellow=2 orange=1 big_orange=1
```

It does so by accepting detections with only one ROI point:

```text
blue raw=2 roi=1 cl=0 assigned_sparse
yellow raw=2 roi=1 cl=0 assigned_sparse
```

This is useful as an upper-bound experiment, but it is riskier for false positives.

## Recommendation

Best first production candidate:

```text
sparse_near_min_points: 4
sparse_mid_min_points: 2
sparse_far_min_points: 2
sparse_bbox_margin_px: 4.0
sparse_bbox_margin_ratio: 0.15
```

Reason:

- It is the smallest effective change.
- It recovers one missed yellow cone.
- It does not expand bbox margin.
- It does not accept 1-point sparse detections.

Use `c07_aggressive_points` only as an optional second-stage experiment after
RViz visual inspection, because it accepts 1-point sparse detections.
