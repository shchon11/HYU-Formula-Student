## Result

PASS: sparse threshold relaxation improved fusion output.

Baseline `/cones` repeatedly published:

```text
blue_cones: 1
yellow_cones: 0
orange_cones: 0
big_orange_cones: 2
```

Sparse experiment `/cones_sparse_exp` repeatedly published:

```text
blue_cones: 1
yellow_cones: 1
orange_cones: 0
big_orange_cones: 2
```

The additional cone is a yellow cone recovered by sparse association.

Direct support evidence from `/fusion/debug_sparse_exp/bbox_support`:

```text
1:yellow raw=4 roi=2 cl=0 assigned_sparse
```

Baseline `/fusion/debug/bbox_support` did not assign that yellow detection.
It only showed the strong cluster assignments:

```text
0:big_orange ... assigned_cluster
2:blue ... assigned_cluster
10:big_orange ... assigned_cluster
```

## Interpretation

The previous diagnosis was correct:

- The projection contract is not globally broken.
- Strong LiDAR-supported detections already become clusters.
- At least one missed cone has enough bbox-aligned ROI support for sparse recovery
  but not enough cluster support.
- Relaxing sparse thresholds recovers that cone without needing cluster tuning.

This experiment does not solve all misses:

- `raw=0` detections remain no-LiDAR-support cases.
- `raw>0, roi=0` detections still indicate ROI/self-mask/ground filtering.
- Some `raw=2 roi=1 cl=0` detections still fail sparse support.

## Recommendation

Apply sparse tuning first, not cluster tuning:

```text
sparse_near_min_points: 3
sparse_mid_min_points: 2
sparse_far_min_points: 2
sparse_bbox_margin_px: 8.0
sparse_bbox_margin_ratio: 0.25
```

Then re-run RViz and watch for false positives. If false positives appear,
reduce margin before changing cluster parameters:

```text
sparse_bbox_margin_px: 6.0
sparse_bbox_margin_ratio: 0.20
```

Do not lower `cluster_min_points` yet. The current experiment proves that sparse
association can recover a missed cone with lower risk.
